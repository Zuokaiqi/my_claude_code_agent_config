# 确认格式（第3步知识点清单、第4步页序大纲）

发确认或落盘前读本文件。格式固定，不自选形式。第4步页序大纲2026-08-07起不设确认门，本文件的页序格式用于落盘备查。

## 备课文档排布

- 标题、来源和课程定位摘要放在最前面，紧跟其后放当前权威内容区（当前生效的知识点清单、页序大纲等）。用户打开文档第一屏必须看到当前决策，不许被修订记录压到下面（2026-07-22用户纠正：最新内容放最上层）。
- 当前权威内容区之后放`## 最新修订记录（最新在前）`。
- 每条修订用`### YYYY-MM-DD 修订主题`作为锚点，按时间倒序排列。同一天有多条时，后发生的放前面。
- 新修订插在修订区第一条之前，旧记录保留，不追加到文件末尾。
- 历史基线、已替代页序和废止方案放在修订记录之后。

## 知识点清单确认

1. 先发知识架构图（2026-08-07用户定，治知识点离散）：SVG文件，画法照SKILL第3步第5条，模块为块、块内列知识点、权重视觉分级、模块间画依赖或递进关系、不教内容放图外缘灰区。对话里发文件路径加模块摘要（每模块一行：模块名+一句话讲什么+核心点数），用户先在图上判断模块全不全、关系对不对、核心给得对不对。
2. 再发困惑链图（2026-08-07用户定）：SVG文件，画法照SKILL第3步第5条，环节点串成链、主环转折突出、配色呼应模块。用户在图上逐环检查问题冒不冒得出来、回答顺不顺，按环号提修改。逐环文字版落盘plan文档备查，每环一行三段（环号、学员的问题用学员的话写、一句话回答），节点内文字照此口径，例：

   ```
   1. LLM为什么只会说不会干活？ → 它本质是预测模型，训练时只学了接话
   2. 那想让它干活怎么办？ → 干活的本质是运行电脑命令，得有东西替它执行
   3. 谁替它执行？ → Harness在你本地跑命令，充当它的手脚
   ```

3. 挂环知识点表落盘plan文档备查，对话只发路径不整表刷屏；用户按模块名或编号点名时再展开对应部分。表仍是每个模块一张、七列：知识点、权重（核心/次要/提及；核心点由用户点名，AI标的只算建议）、挂链上哪一环（环号）、所属模块、学完达到什么状态、来源、陌生概念（对学员陌生则写联想桥用哪个旧概念，不陌生留空）。编号跨模块全局连续，方便用户按编号提修改。来源只允许四种标注：项目事实、用户口述、AI补充已核、AI补充未核；标「已核」的必须在plan文档附一行来源（链接或文档名加关键结论），没有来源一律标未核进待确认项。挂不上环的知识点不进表，进待确认项。
4. 之后给「不教清单」：知识域完整性判断（SKILL第3步第4条）里决定不教的部分，每条一句为什么不教（超出定位、学员用不上、留给后续课）。取舍本身要摆出来让用户确认，不许默默跳过。
5. 倒推视图（能力块 ← 缺什么知识）降级为可选：架构图和链已覆盖依赖关系时不发，用户点名要备料视角再发。
6. 最后固定跟「待确认项」，集中列AI拿不准的假设。
7. 固定问法收尾：直接回复确认，或按模块名、环号、编号说改哪条。

## 页序大纲确认

- 开头一行总量：共几页、几章、核心/次要/提及知识点各占几页；时长栏只在用户已给口径时填，没给就整体省略（红线5）。
- 按章节分组，每章标页码范围（用户给了时长口径时附每章分钟数），章内表格六列：页码、页标题、所属知识点权重、认知任务、这页回答的问题、页型与素材需求。页标题用知识名词，问句只写在「这页回答的问题」列，两列不互串；认知任务写成「从不懂X到懂Y」，一格只许一个，装不下就拆页；「这页回答的问题」写上一页冒出的那个问题，追问链断没断，用户扫一遍就能看出来。
- 每页在「页型与素材需求」列附引入的陌生概念数；超过1个的页给拆页方案或一句理由。
- 带做类知识点标检验位置（哪页收成果）；认知类默认不检验，无需写豁免理由。
- 表格后列「素材缺口」：哪几页缺真实截图、logo、回放素材。这块是知会不是门槛，默认用占位继续做，占位页交付时集中列入待确认项。
- 本大纲落盘备查，不再发确认（2026-08-07用户定）；用户主动查看后按页码提修改。
